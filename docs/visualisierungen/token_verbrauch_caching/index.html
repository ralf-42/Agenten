Inference Gateway: Der Baustein zwischen Cache und LLM. Er entscheidet, ob KV-States aus dem Cache geladen oder neu berechnet werden, und leitet den vollständigen Kontext ans Modell weiter. Bei Cloud-APIs (Anthropic, OpenAI) ist dieser Baustein Teil der Infrastruktur — für Nutzer unsichtbar, aber immer aktiv.

① Pipeline: Jede Anfrage läuft durch Cache-Check → Inference Gateway → Kontext laden → LLM. Der Gateway entscheidet: KV-States laden (Hit) oder volle Inferenz anfordern (Miss).

② Kontextfenster: Das LLM bekommt immer alle vier Teile (~660 Tok.). Bei einem Miss wird der vollständige Prompt aufgebaut — der Cache spart Rechenzeit, ändert aber nicht, was das LLM sieht.

Rechenaufwand: Cache Miss = Attention-Berechnung (Q/K/V) für alle ~660 Token neu durchgeführt. Cache Hit = K/V-Vektoren für ~600 Token aus Cache geladen, nur ~60 Token (Anfrage) neu berechnet.

LRU-Prinzip: Ist der Cache voll, fliegt der am längsten nicht genutzte Eintrag raus.
